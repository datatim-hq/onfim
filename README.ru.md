# Onfim

[English](README.md) · **Русский**

**Долговременная память для ИИ-агентов, которая может объяснить, что она помнит и почему.**

Onfim — сервис памяти для агентов (Claude Code, Claude Desktop, Cursor, ваши собственные боты), который вы
разворачиваете у себя. Он работает на Postgres + pgvector, считает эмбеддинги локально и даёт одни и те же операции
через REST и MCP.

> **Статус: до выпуска (готовится 0.1).** Доделываются упаковка, документация и быстрый старт.

## Чем это отличается от векторного хранилища

- **У каждого факта есть доказательства.** Каждая запись хранит свои источники: кто сказал, когда и короткую цитату.
- **Сила, а не только сходство.** Знание набирает силу от независимых подтверждений и использования и затухает с
  периодом полураспада, своим для каждого вида. Ранжирование сочетает релевантность и силу по описанной формуле.
- **Слоты и замена.** Новое утверждение заменяет старое, только когда оно подтверждено (шлюзы G1–G3); спорные
  изменения уходят в очередь решений к человеку, с историей и откатом.
- **Сон.** Лёгкий сон (каждую ночь, детерминированный) и глубокий сон (раз в неделю, при желании с LLM, которая только
  *предлагает*; каждое предложение проходит детерминированные проверки) наводят порядок, сливают дубли и честно
  отчитываются.
- **Сервис никогда не переписывает то, что прислал клиент.** На пути записи нет LLM.
- **Модель доступа с первого дня.** Организации, люди, вложенные группы, слои памяти (личный → команда → организация),
  гранты, уровни классификации, защита на уровне строк в Postgres. Агент никогда не видит больше, чем его человек.
- **Защита от отравления.** Правила из недоверенных источников ждут подтверждения, скрытые символы Unicode
  вырезаются, секреты не принимаются, связанные цитаты не считаются независимыми подтверждениями.

## Устройство репозитория

| Путь | Что там |
|---|---|
| `mem/` | сервис (пакет Python `mem`): бизнес-логика в `service.py`, `api.py` и `mcp_server.py` — тонкие адаптеры |
| `migrations/` | схема SQL; сервис не запустится, если схема, модель эмбеддингов или размерность не совпадают |
| `tests/` | модульные и интеграционные тесты; что проверяет каждый тест — в реестре `docs/tests.md` |
| `docs/ru/design/` | спецификации 00–09 (перевод на английский — в `docs/design/`); главная — `05-lifecycle.md` |
| `tools/` | бенчмарк эмбеддингов, сборщик реестра тестов и проверка быстрого старта, которая идёт в CI |

## Запуск тестов

```bash
docker compose -f docker-compose.test.yml run --rm --build tests
```

Интеграционные тесты используют одноразовый Postgres в tmpfs и детерминированные фальшивые эмбеддинги.

## Запуск сервиса

```bash
cp .env.example .env && sed -i "s/change-me/$(openssl rand -hex 16)/" .env
docker compose up -d                                   # API and MCP on 127.0.0.1:3120
docker compose exec api python -m mem.cli init --tenant acme --person alice --name "Alice"
docker compose restart api                             # MCP picks up the new namespace
```

`init` один раз печатает токен и адрес MCP (`/mcp/alice.work/`). Прежде чем открывать сервис наружу, поставьте его за
обратный прокси с TLS ([эксплуатация](docs/ru/operations.md#running-behind-a-tls-reverse-proxy)), затем подключите
Claude Code, Claude Desktop или Cursor, как описано в [подключении клиентов](docs/ru/connect-clients.md).
