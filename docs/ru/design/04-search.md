# 04. Поиск и ранжирование

[English](../../design/04-search.md) · **Русский**

## Назначение

Находить нужную запись по вопросу своими словами — на русском и английском — и объяснимо ранжировать результат. У прежнего сервиса ранжирование было недетерминированным и неверным; здесь формула фиксирована, покрыта тестами и видна в ответе (`explain=true`).

## Алгоритм [DET]

1. **Фильтры** (всегда до ранжирования): пространство; `state = current` (претенденты — только при `include_candidates`, архив — при `include_archived`); действовавшие на `as_of`, если задан; `kind`, `subject`, `slot`, `tags` (`any` — пересечение, `all` — вхождение), даты; `duplicate_of is null`; **граница раскрытия** — при заданном `audience` (ниже).
2. **Кандидаты:** объединение топ-50 по вектору (косинус, HNSW) и топ-50 по полнотекстовому поиску (`websearch_to_tsquery` для `russian` и `english`, берётся максимум).
3. **Оценка** каждого кандидата:

```text
score = 0.50 · sem  +  0.20 · lex  +  0.20 · strength  +  0.10 · prior
  sem      = косинусное сходство, нормированное в [0,1] внутри кандидатов (min-max)
  lex      = ts_rank_cd, нормированный в [0,1] внутри кандидатов; 0, если нет совпадения
  strength = текущая сила записи с учётом затухания на момент запроса (05, §1)
  prior    = kinds.rank_weight × (importance / 3)
```
4. **Сортировка** по `score` убыв., при равенстве — `created_at` убыв., затем `id` (полная детерминированность).
5. Записям, попавшим в топ-5, пишется событие `recalled_top5` (не чаще раза в сутки, подкрепление 0,03 — 05). Запись — после ответа, ошибка не влияет на выдачу.
6. В ответе по каждой записи: `strength`, `evidence_count`, до трёх доказательств (`source_ref`, `speaker`, `observed_at`, `quote`), `contested` и id претендента, если есть спор в слоте (05, §2).

Веса — константы в конфигурации, меняются только вместе с тестами (набор эталонных запросов, 07).

## Граница раскрытия (`audience`)

Личное не должно всплывать там, где его не должны слышать. Для пространства `assistant` это важно в автоответах агента.

| `visibility` записи | Видна при `audience = chat:X`, если |
|---|---|
| `shareable` | всегда |
| `same_chat` | хотя бы одно доказательство записи из чата X |
| `owner_only` | никогда (только без `audience`, то есть для самого владельца) |

Без `audience` (брифинг владельцу, `/ask`, Cowork) видно всё. Значение `visibility` при записи задаёт клиент; агент по умолчанию ставит `same_chat` для фактов из личных чатов и `shareable` — из рабочих групп.

## Эмбеддинги

- Модель выбирается бенчмарком (07, M-E1) из трёх многоязычных кандидатов; критерий — разделение: перефразы одного факта должны быть ближе, чем разные факты с одинаковым шаблоном фразы (урок: «три разные сметы» у openai-small дали 0.97, «разные факты об одном человеке» — 0.63).
- Префиксы моделей e5 (`query:` / `passage:`) добавляются сервисом автоматически.
- Смена модели = миграция: новая колонка, пересчёт всех векторов пакетно, переключение, удаление старой.

## Функциональные требования

| ID | Требование | Соавт. | Тип |
|---|---|---|---|
| R-1 | Одинаковый запрос на неизменных данных всегда даёт одинаковый порядок | 4 | DET |
| R-2 | `explain=true` возвращает `sem`, `lex`, `strength`, `prior` и итог для каждой записи | 4 | DET |
| R-3 | Фильтр по тегам и пространству применяется до ранжирования, а не после (никаких «похожих» чужих записей) | 4 | DET |
| R-4 | Пустой `query` → `list` с сортировкой по `strength`, затем `created_at` | 4 | DET |
| R-5 | При заданном `audience` запись с `owner_only` или `same_chat` из другого чата не попадает в выдачу ни при каком запросе | 4 | DET |

## Критерии приёмки

- Recall@10 ≥ 0,8 и MRR ≥ 0,6 на эталонном наборе из 20 пар «запись — вопрос другими словами» (русский, пространство `assistant`) и 10 пар для `work` (смешанный русский/английский).
- Запрос с точным редким токеном (например, `EMBEDDING_MODEL`) ставит запись с этим токеном на первое место.
- Повторный запуск набора на неизменных данных и том же `as_of` даёт идентичные списки (тест на детерминированность; сила зависит от времени, поэтому тест фиксирует момент).
- Из двух одинаково релевантных записей выше та, у которой больше независимых подтверждений.
- `recall(audience=chat:A)` не возвращает факт с `visibility=same_chat`, известный только из чата B.
