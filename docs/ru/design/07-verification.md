# 07. Проверка и приёмка

[English](../../design/07-verification.md) · **Русский**

## Назначение

Проверить mem тем же методом, которым проверяли прежний сервис памяти: канарейки с заранее записанным исходом, снимки «до/после», недоверие к самоотчёту системы. Критерии приёмки из спек 00–06 оформлены как автотесты там, где это возможно.

## Уровни проверки

| Уровень | Что | Где |
|---|---|---|
| Unit | Сервисный слой, правила, формула ранжирования, нормализация дублей | `tests/unit`, CI |
| Интеграция | Postgres + модель в контейнере: REST и MCP, миграции, инварианты D-1…D-6 | `tests/integration`, CI (docker compose) |
| Канарейки | 42 канарейки из проверки прежнего сервиса, перенесённые в формат mem (`tools/memlab.py`) | стенд до переключения клиентов |
| Эталонный поиск | 30 пар «запись — вопрос» (20 assistant, 10 work) | CI + стенд |
| Мониторинг | ежедневно в проде | скрипт мониторинга |

## Тест-кейсы на канарейках

Время моделируется: тестовый стенд умеет сдвигать «текущее время» сервиса (`MEM_CLOCK_OFFSET`, только в режиме стенда), поэтому затухание, продвижение претендентов и забывание проверяются за минуты, а не за месяцы. Урок прежней проверки: без этого консолидацию пришлось «старить» SQL-запросами.

### Виды и доказательства

| ID | Проверка | Критерий «прошло» | В прежнем сервисе |
|---|---|---|---|
| M-L1 | Вид не меняется | 42/42 `kind` совпадают с записанным через 10 мин, после лёгкого и глубокого сна | V-L1 ❌ |
| M-L2 | Классификатора нет | Запись без `kind` или без `evidence` → 400 | V-L2 ❌ |
| M-E0 | Доказательства в выдаче | `recall` по «когда удобно Чижову» возвращает запись и цитату с датой и говорящим | паттерн без источников |

### Сила (ранжирование знаний)

| ID | Проверка | Критерий |
|---|---|---|
| M-S1 | Не выравнивается | После 60 смоделированных ночей: стандартное отклонение силы 42 канареек ≥ 0,1; ни одна запись не выросла без события |
| M-S2 | Подкрепление работает | Запись с 3 независимыми доказательствами сильнее такой же с 1 (и выше в выдаче при равной релевантности) |
| M-S3 | Повтор ≠ подтверждение | 5 одинаковых доказательств от одного источника дают прирост < одного независимого |
| M-S4 | Использование держит | c901 (`topic_fact`) с `used` раз в 20 дней держит силу > 0,5 весь модельный год; c903 без событий опускается ниже 0,2 (до порога забывания `topic_fact` — около 500 дней, `person_fact` — около 1000: за год факт о человеке не забывается, и это правильно) |
| M-S5 | Нет «шумовой элиты» | В `assistant` нет записей, которые сервис создал сам вне глубокого сна; ни одна запись не имеет силы > 0,9 без ≥ 3 событий подкрепления |

| ID | Проверка | Критерий |
|---|---|---|
| M-E1 | Выбор модели | для трёх моделей — таблица сходства по группам канареек; выбирается модель с Recall@10 ≥ 0,8 и наибольшим MRR на эталонных вопросах. «Зазор» перефразы/шаблон — справочно: ни одна модель не разводит «три сметы» (24.09, `docs/research/embed-benchmark.md`), защита от слияния — структурная. **Выбрана `intfloat/multilingual-e5-small` (384)** |

## Мониторинг в эксплуатации

`/status/<секрет>` отдаёт: `memories` по пространствам и состояниям, распределение силы (квартили), `lastLightSleep` и `lastDeepSleep` (время, статус), число открытых пунктов `review`, `embedDim`, `modelId`, `dbOk`. Датчики (добавляются в скрипт мониторинга на сервере и задачу ассистента):

| Датчик | Порог |
|---|---|
| `lastLightSleep.status` / возраст | `OK` / ≤ 30 ч |
| `lastDeepSleep.status` / возраст | `OK` / ≤ 8 суток |
| открытых `review` старше 14 дней | 0 (иначе — напоминание в брифинге) |
| медиана силы | не равна 1-му и 3-му квартилю (признак «выравнивания», как у прежнего сервиса) |
| `dbOk` | true |
| ответ `/status` | ≤ 2 с |
| бэкап mem | ≤ 30 ч |

## Критерии завершения пилота

- Все кейсы таблицы — «прошло».
- Эталонный поиск: Recall@10 ≥ 0,8, MRR ≥ 0,6.
- 7 дней в проде без `FAILED` и без жалоб «не нашлось».
