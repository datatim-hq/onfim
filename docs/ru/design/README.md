# Onfim (mem) — проектные спецификации

[English](../../design/README.md) · **Русский**

> Продукт — Onfim, пакет и сервис в коде — `mem`. Спеки написаны по-русски во время разработки; перевод на английский —
> в [`docs/design/`](../../design/README.md).
> Статус: **v0.3** (08 — модель доступа, 09 — память команды); v0.2 — сон, сила, замещение, забывание.

## Зачем

Проверка прежнего сервиса памяти (23–24.09.2026) показала: как хранилище он работает, но всё, что он делает «сам» — раскладка по слоям, консолидация, забывание, отчёт о сне, — либо не работает, либо работает так, что на результат нельзя опираться. Другие готовые решения, которые мы смотрели, тоже не дают надёжного забывания. Решено: **своя память на Postgres, где каждое автоматическое действие — явное правило с тестом**. При этом сохраняется логика, ради которой брали прежний сервис: **циклы сна, ранжирование знаний по силе, замещение старых суждений подтверждёнными новыми, забывание** (05). Дополнительно: доказательства с цитатами у каждого факта, еженедельная уборка с отчётом «протухло / расхождения», граница раскрытия личного.

Клиенты:
1. **Личный агент-ассистент** — память о людях, чатах, темах (пространство с профилем `assistant`).
2. **AI-ассистенты разработки (Claude Code, Claude Desktop, Cursor)** — рабочая память разработки: решения на лету, грабли, конвенции (пространство `work`).

## Принципы (выведены из дефектов прежнего сервиса)

| # | Принцип | Какой дефект прежнего сервиса закрывает |
|---|---|---|
| P1 | **Сервис не переписывает то, что прислал клиент.** Никакого LLM на пути записи: текст, вид (`kind`), слот, теги, важность сохраняются как есть. Меняются только состояние и сила — по правилам 05 | LLM-извлечение переписывало явный слой; классификатор слоёв не работал на русском |
| P2 | **Каждое автоматическое действие — формула или ворота (G1–G3) из 05,** с записью в журнал и тестом; LLM глубокого сна только предлагает, результат проходит детерминированную проверку | Забывание по «важности», которая у всех одинакова; сводка сна исказила дату |
| P3 | **Старое суждение заменяется только подтверждённым новым**: явно клиентом или через слот и ворота G1 (новее + подтверждено независимо / владельцем / самим автором); спорное — в очередь человеку; история и откат 30 дней | Противоречия не обрабатывались |
| P4 | **Удаление — настоящее** (purge), мягкое удаление — отдельная операция | `DELETE` оставлял текст и вектор |
| P5 | **Отчёт ночной задачи честный:** любая ошибка стадии → статус `FAILED`/`PARTIAL` и алерт | `COMPLETED` при упавшей консолидации |
| P6 | **Ранжирование поиска описано формулой и покрыто тестами** | Константный score, сломанное слияние BM25 |
| P7 | **Фильтр по тегам и пространству работает одинаково через REST и MCP** — один код | Теги через MCP игнорировались |
| P8 | **Никаких служебных записей в пространствах клиентов** | Сущности и маркеры вытесняли содержательное |
| P9 | **Эмбеддинги считаются локально** — тексты не уходят внешним провайдерам | Факты из личных переписок уходили в OpenAI |
| P10 | **Схема базы = миграции**, CI проверяет расхождение | Enum `DREAM_CYCLE` был в схеме, но не в миграциях |
| P11 | **Сила знания — отдельная величина, не важность**: растёт от независимых подтверждений и использования, затухает по полураспаду вида, пересчёт никогда не повышает силу | Пол 0,35 выравнивал всю память, служебные записи получали 1,0 |
| P12 | **У каждого факта есть доказательство** (источник, говорящий, дата, короткая цитата); ответы и отчёты уборки показывают цитаты | Паттерн сна без связи с источниками |
| P13 | **Граница раскрытия**: запись знает, где её можно показывать (`visibility`), поиск с `audience` это соблюдает | — |
| P14 | **Корпоративная модель доступа с первого дня**: организации, участники, вложенные группы, слои памяти (личный → команда → отдел → организация), гранты с ролями и уровни конфиденциальности записей; агент никогда не видит больше своего человека; фильтр — в SQL до ранжирования (08) | Прежний сервис: один пользователь, доступ «всё или ничего» |
