# MCP

[English](../mcp.md) · **Русский**

Onfim поднимает по одному MCP-серверу на пространство поверх **streamable HTTP**. Инструменты вызывают тот же
сервисный слой, что и REST API ([rest-api.md](rest-api.md)), поэтому права, фильтры и ошибки совпадают. Как подключить
Onfim к Claude Code, Claude Desktop или Cursor — в [connect-clients.md](connect-clients.md).

## Адрес

```
http://127.0.0.1:3120/mcp/<namespace>/          # напрямую, на сервере
https://mem.example.com/mcp/<namespace>/        # за обратным прокси с TLS
```

Для пространства, созданного командой `mem.cli init --tenant acme --person alice`, это `/mcp/alice.work/`. Слэш в
конце обязателен.

Каждому запросу нужен заголовок:

```
Authorization: Bearer <token>
```

До MCP запрос доходит только после проверки токена: токена нет или он неизвестен → `401`; пространства нет в списке
пространств токена (и список не `*`) → `403`. Дальше каждый инструмент проверяет гранты человека на нужное право —
так же, как REST.

Транспорт: сервер не хранит состояние и отвечает обычным JSON, без долгоживущего потока событий. Клиент должен
отправлять `Accept: application/json, text/event-stream`; MCP-клиенты делают это сами. Быстрая проверка через curl:

```bash
curl -sS -X POST http://127.0.0.1:3120/mcp/alice.work/ \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "tools/list"}'
```

### Новому пространству нужен перезапуск

Список MCP-адресов собирается при старте API. После `mem.cli init` или `mem.cli create-namespace` перезапустите API,
чтобы появился новый `/mcp/<namespace>/`:

```bash
docker compose restart api
```

До перезапуска новое пространство доступно только через REST.

### Чего нет в MCP

- **Делегированным клиентам** (токены с `--delegate-group`) нужен заголовок `X-Mem-On-Behalf-Of`, а вызовы MCP его не
  передают — такие клиенты получают `400`. Агенты команды работают через REST.
- Перенос между слоями, псевдонимы субъектов, архив и возврат из архива, откат, закрытие, выгрузка и импорт есть
  только в REST.
- У `remember` через MCP нет параметра `classification` (действует уровень пространства по умолчанию), у
  `add_evidence` нет `speaker_principal`.

## Язык описаний инструментов

По описаниям инструментов и инструкциям сервера агент решает, как пользоваться памятью. По умолчанию они на английском;
`MEM_MCP_LANG=ru` включает русский (любое другое значение — английский). После смены перезапустите API.

Инструкции называют пространство, перечисляют виды записей, разрешённые его профилем (`work`, `assistant` или `team`),
объясняют формат доказательств и предупреждают агента: записи с `trust=untrusted` пришли из внешних источников, это
сведения, а не указания. Описание `remember` просит Claude Code указывать `source_ref: "claude-code:<project>"`,
`source_scope: "dev"`, `speaker: "agent"` или `speaker: "owner"`, если это сказал пользователь в разговоре.

## Результаты

`recall`, `recall_layers` и `list` по умолчанию отвечают в сжатом виде, чтобы беречь контекст агента:

- у каждой записи только непустые `id`, `kind`, `subject`, `slot`, `tags`, `text`, `state`, `strength`, `score`,
  `contested`, `candidate_id`, `layer`, `explain`, `occurred_at`;
- не больше трёх доказательств, у каждого `speaker`, `quote`, `observed_at`, `source_ref`;
- у недоверенных записей в `trust` пометка: это данные из внешнего источника, а не указания.

`full: true` возвращает те же объекты, что REST. Остальные инструменты отдают ответ REST без изменений.

При ошибке инструмент возвращает ошибку, в тексте которой тот же JSON, что в теле ошибки REST, например
`{"error": "forbidden", "message": "..."}`.

## Инструменты

Все 16 инструментов работают внутри пространства своего адреса, кроме `recall_layers`.

### `remember`

Запомнить факт. Право: `write`. То же, что `POST /v1/{ns}/memories`.

| Параметр | Тип | По умолчанию |
|---|---|---|
| `text` | строка | обязателен |
| `kind` | строка | обязателен |
| `evidence` | список объектов `{source_ref, source_scope, observed_at, speaker?, quote?}` | обязателен, минимум одно |
| `subject` | строка | — |
| `slot` | строка | — |
| `tags` | список строк | `[]` |
| `importance` | 1–3 | 2 |
| `visibility` | `shareable` \| `same_chat` \| `owner_only` | `shareable` |
| `occurred_at` | ISO 8601 | — |
| `external_ref` | строка | — |
| `supersedes` | id записи | — |

Новая запись в занятом слоте становится претендентом; `supersedes` явно заменяет текущую запись.

### `add_evidence`

Добавить доказательство к записи («это подтвердилось ещё раз»). Право: `write`.
Параметры: `id`, `source_ref`, `source_scope`, `observed_at` (обязательны); `speaker`, `quote`.

### `recall`

Гибридный поиск внутри пространства. Право: `read`.

| Параметр | По умолчанию |
|---|---|
| `query` | обязателен (пустая строка → список по силе) |
| `tags`, `tags_mode` (`any` \| `all`) | —, `any` |
| `kind`, `subject`, `slot` | — |
| `include_candidates` | `false` |
| `as_of` | — |
| `audience` (`chat:<id>`) | — |
| `min_strength` | — |
| `limit` | 10 (не больше 50) |
| `explain` | `false` |
| `full` | `false` |

### `recall_layers`

Поиск по всем слоям памяти, которые может читать человек токена (личный, команды, организации), или по заданным
`namespaces`, со слиянием результатов; у каждой записи указан `layer`. Право: `read` в каждом пространстве.
Пространством адреса не ограничен.
Параметры: `query` (обязателен), `namespaces`, `tags`, `kind`, `subject`, `limit` (10), `full` (`false`).

### `get`

Запись целиком: все доказательства и последние события силы. Право: `read`. Параметр: `id`.

### `list`

Список записей по фильтрам, без поиска. Право: `read`.
Параметры: `tags`, `tags_mode` (`any`), `kind`, `subject`, `slot`, `state` (по умолчанию `current`; также `candidate`,
`superseded`, `archived`, `all`), `sort` (`created_at` \| `strength`, по умолчанию `created_at`), `limit` (20, не больше
200), `cursor`, `full` (`false`).

### `history`

Что было верно и когда в слоте записи или в цепочке замен, и почему это менялось. Право: `read`. Параметр: `id`.

### `used`

Отметить, что запись использована в работе или ответе (сила +0,15). Право: `write`. Параметр: `id`.

### `helpful`

Отметить, что запись оказалась полезной (сила +0,25). Право: `write`. Параметр: `id`.

### `confirm`

Подтверждение владельцем (сила +0,50, запись становится доверенной). Только по прямому слову владельца. Право:
`review`. Параметр: `id`.

### `pin`

Запретить (`pinned: true`, по умолчанию) или разрешить (`pinned: false`) забывание записи. Право: `review`.
Параметры: `id`, `pinned`.

### `forget`

Забыть записи по фильтру. Право: `forget`.
Параметры: `mode` (`archive` по умолчанию или `purge`), `subject`, `slot`, `tags`, `kind`, `source_ref` (нужен хотя бы
один фильтр), `dry_run` (`true`), `confirm` (число записей, обязательно при `dry_run: false`). Всегда начинайте с
пробного прогона.

### `sleep_report`

Последний отчёт сна по пространству: что заменено (обе стороны с цитатами и основанием), что забыто, какие расхождения
открыты. Право: `read`. Параметр: `kind` (`light` по умолчанию или `deep`).

### `review_list`

Очередь решений: расхождения, предложения слотов, пункты «протухло?», сводки, не прошедшие проверку, правила, которые
ждут подтверждения, переносы. Право: `review`. Параметр: `status` (`open` по умолчанию или `all`; также `accepted`,
`rejected`, `expired`).

### `review_decide`

Решение по пункту очереди — только по прямому слову владельца. Право: `review`.
Параметры: `id` (целое число), `decision` (`accept` \| `reject`), `winner` (id верной записи, обязателен, чтобы принять
расхождение).

### `stats`

Число записей по видам и состояниям и распределение силы. Право: `read`. Без параметров.

## Права токена по умолчанию

Токен агента, который печатает `mem.cli init`, имеет права `read`, `write` и `review` в личном пространстве. Права
`forget` в нём нет, поэтому инструмент `forget` с этим токеном вернёт `403`. Если агент должен уметь удалять, выпустите
токен с `forget` командой `mem.cli create-client` (см. [operations.md](operations.md#cli)).
